## Findings

- `code6` 的核心收益来自 shared layout 重做，而不是改变 `DMMA` 数量或计算路径。
- `code6` 将 shared staging 从带 padding 的二维线性布局，改成与 WMMA fragment 对齐的 `8x4` / `4x8` packed block。
- 这样做后，`wmma::load_matrix_sync` 读取的 shared 区域更连续，shared bank conflict 预期更低，地址计算也更简单。
- `ptxas` 统计显示 `code6` 的 stack frame 从 64 bytes 降到 32 bytes，寄存器略增但没有 spill。
- `nsys` 显示 `report6` 的 kernel time 为 `5.631 s`，优于 `report5` 的 `6.915 s` 和 `report5-2` 的 `6.058 s`。
- `nsys` API 侧仍明显受 `cudaMemcpy` 影响，说明下一步如果追求端到端时间，应该先考虑传输重叠/驻留，而不是继续只调 shared layout。
