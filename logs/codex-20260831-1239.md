## Findings

- `report7.sqlite` 没有 `CUPTI_ACTIVITY_KIND_KERNEL` 表，因此 Nsight Systems 跳过了 `cuda_gpu_kern_sum.py`。
- `CUPTI_ACTIVITY_KIND_RUNTIME` 里唯一的失败项是 `cudaLaunchKernel_v7000`，`returnValue = 701`。
- `GPU_CONFIG.md` 和 `report7.sqlite` 记录的设备都是 A800 80GB PCIe / GA100，`maxRegistersPerBlock = 65536`。
- `code6.cu` 当前是 `32 x 16` block，`512` threads/block；`ptxas` 记录为 `240 registers/thread`。
- 这意味着单个 block 需要约 `122880` 个 32-bit registers，超过了该 GPU 的每 block 寄存器上限，所以 kernel 没有成功启动。

## Notes

- 这不是 shared-memory bank conflict 本身导致的性能退化，而是 launch 资源不足导致 kernel 根本没有发射。
- 后续如果要让 `code6.cu` 先跑起来，需要先降寄存器压力或调整 block/warp 组织；仅继续调 swizzle 不会解决当前报错。
